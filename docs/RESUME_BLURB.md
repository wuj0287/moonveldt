# wwj 项目 — 简历 / 面试话术草稿

> 写于 2026-09-05，v1.9.1 封版时点，趁记忆新鲜固化。三个版本对应三种场合，数字均可核实（git log 15+ 版迭代、README 功能表）。

## 一、简历版（3–4 行，可直接贴）

**wwj — 可执行 Markdown 工作台（Electron + Python，个人独立开发）** · 2026.07–2026.09

- 独立设计并开发 Windows 桌面应用，15+ 版本迭代，支持 CI 式本地打包（electron-packager / electron-builder NSIS 双产物）与 GitHub Release 分发
- 实现"可执行文档"核心链路：Markdown 文档内 Python 代码块一键运行、输出嵌入文档，缺依赖自动检测 → 一键安装 → 自动重跑的闭环体验；每块独立进程互不干扰
- 实现专业编辑器级"即时渲染"：渲染结果即编辑面，基于 contenteditable + HTML→Markdown 双向转换（Turndown），光标精确落点、增量渲染、滚动定位
- 内置 Mermaid / KaTeX / 代码高亮全离线渲染；粘贴图片自动 base64 内嵌，旧文档图片引用自动迁移，实现 .md 单文件自包含

**技术栈**：Electron、Node.js（主进程 IPC / 子进程管理 / venv 环境管理）、原生 JavaScript、Markdown AST、Turndown、Mermaid、KaTeX

## 二、面试口头版（60 秒）

"wwj 是我独立开发的桌面应用，定位是'可执行 Markdown 工作台'。出发点是我自己记学习笔记时，文档里的代码要切到 IDE 跑、结果再抄回来，链路断了。所以我把 Python 运行做进了文档：代码块直接跑、输出嵌在文档里，报缺包还会自动装好重跑。技术上最有挑战的是即时渲染编辑器——渲染结果就是编辑面，等于在浏览器 DOM 上做了一套 HTML 和 Markdown 的双向转换，要处理光标定位、增量渲染、滚动同步这些编辑器工程问题。前后迭代了 15 个版本，从纯编辑器长到带环境管理面板的开发工具。这个项目让我对 Electron 进程模型、IPC 设计和子进程管理有了实打实的手感。"

## 三、导师提案一句话版（入学面谈用）

"我在入学前独立做了一个可执行 Markdown 工作台（Electron + Python），验证了我从需求分析、交互设计到桌面端工程化的完整交付能力；下一步我想把同样的'文档即上下文、输出即文档'思路用到 LLM Agent 应用上——这也是我对贵组 LLM 工业应用软件方向的理解和准备。"
